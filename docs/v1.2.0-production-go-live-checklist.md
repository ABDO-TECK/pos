## 3. Database Migration Execution Sequence

When executing updates on POS terminals, migrations run in strict sequential order:

```mermaid
graph LR
    M045[045_create_update_history_table.sql] --> M046[046_extend_update_history_table.sql]
    M046 --> M047[047_seed_update_permissions.sql]
    M047 --> M048[048_add_update_channel_and_rollout.sql]
    M048 --> M049[049_create_update_telemetry_table.sql]
    M049 --> M050[050_add_update_recovery_permissions.sql]
```

1. **`045_create_update_history_table.sql`**: Instantiates initial update transaction log.
2. **`046_extend_update_history_table.sql`**: Adds release tag, source, and download URLs.
3. **`047_seed_update_permissions.sql`**: Seeds base update RBAC permissions (`updates.view`, `updates.check`, `updates.apply`, `updates.rollback`).
4. **`048_add_update_channel_and_rollout.sql`**: Seeds channel permission and adds `channel` / `rollout_percentage` columns.
5. **`049_create_update_telemetry_table.sql`**: Creates high-performance telemetry event ledger.
6. **`050_add_update_recovery_permissions.sql`**: Seeds self-healing permissions (`updates.recovery.view`, `updates.recovery.manage`).

## 6. Rollback Triggers & Emergency Procedures

### Automatic Rollback Triggers (Fleet-wide Alerts):
1. **Update Failure Rate > 5%** across active telemetry reporting terminals.
2. **Auto-Rollback Count $\ge$ 3** in a single rollout phase.
3. **Database Migration Deadlock or SQL Fatal Error**.

### Emergency Response Procedure:
1. **Halt Rollout**: Set `rollout_percentage: 0` in release settings or unpublish GitHub asset.
2. **Publish Fix / Hotfix Tag**: e.g., `v1.2.1`.
3. **Terminal Auto-Recovery**:
   - POS terminals automatically detect interrupted states via `UpdateRecoveryService`.
   - Pre-update file and database snapshots stored in `backend/storage/update-backups/` are automatically restored.
